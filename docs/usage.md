# 操作使用说明

本文面向第一次上手的使用者，按“接线 → 编译烧录 → 上位机 → 卡片 → 进出场 → 配置模式 → MaixCAM → 排障”的顺序说明。
项目总体介绍、目录结构与协议细节见 [README](../README.md)、[协议规范](protocol.md) 和 [硬件说明](hardware.md)。

---

## 1. 硬件准备与接线检查

### 1.1 需要准备的硬件

- STM32F407VETx 开发板（或兼容板）+ ST-Link 下载器；
- RC522 RFID 模块（3.3V）+ Mifare Classic / Ultralight 卡；
- SSD1306 0.96 寸 OLED（I2C，3.3V）；
- 两路 SG90 360° 舵机（道闸）+ 独立 5V 电源；
- 三路红外避障模块（3.3V，低电平有效）；
- USB-TTL 串口模块（3.3V 电平，接上位机）；
- MaixCAM（跑车牌识别，可选）。

### 1.2 接线核对表

| 模块 | 连接到 STM32 |
|---|---|
| 上位机 USB-TTL | PA9(TX) / PA10(RX)，GND 共地，115200-8N1 |
| MaixCAM 串口 | PC6(TX) → MaixCAM RX，PC7(RX) ← MaixCAM TX，GND 共地 |
| RC522 | CS=PA5，SCK=PA7，MOSI=PC4，MISO=PA4，RST=PA6，3.3V |
| OLED | SCL=PB10，SDA=PB11，3.3V |
| 舵机 1（入口） | PB5（TIM3_CH2），50Hz PWM，独立 5V |
| 舵机 2（出口） | PB6（TIM4_CH1），50Hz PWM，独立 5V |
| 红外 P1/P2/P3 | PB0 / PB1 / PB4，上拉输入，低电平=检测到车 |
| 按键 KEY1~KEY4 | PA0 / PA1 / PA2 / PA3，按下为低电平 |

注意：

1. 舵机不要从核心板 3.3V 取电，峰值电流会拉低系统电压；
2. 所有模块必须共地；
3. PB4 复位后默认是 JTAG 的 NJTRST，本工程当普通 GPIO 使用；如果用 JTAG 调试请注意；
4. USART1 同时用于 `printf` 调试输出和上位机协议，同一时刻只能有一个程序占用该串口。

## 2. 编译与烧录（Keil MDK5）

### 2.1 环境

- Keil MDK 5（uVision 5）；
- ARM Compiler 5.06 update 5（AC5）；
- STM32F4xx_DFP 2.17.1（器件包）；
- 目标器件：STM32F407VETx。

### 2.2 编译步骤

1. 打开 `project/MDK(V5)/Project.uvprojx`；
2. 检查 `Options for Target → Device` 是否为 `STM32F407VETx`；
3. 检查 `C/C++` 页：C99 已勾选，宏定义 `USE_STDPERIPH_DRIVER, STM32F40_41xxx`；
4. 点击 `Project → Rebuild all target files`（仓库不含编译产物，首次必须 Rebuild）；
5. 连接 ST-Link，点击 `Download` 烧录到 0x08000000；
6. 复位运行，串口应能看到启动日志（115200）。

> 如果编译报错：优先检查是否安装了 ARM Compiler 5.06 与 STM32F4xx_DFP；工程使用 AC5，不是 AC6。

## 3. 首次上电检查

1. 上电后 OLED 应显示主界面：
   - 第 1 行：`04/30 00:00:00`（软件时钟，默认 2024-04-30，连接上位机会自动校时）；
   - 第 2 行：`CW:P1  P2  P3`；
   - 第 3 行：三个车位的红外状态 `YOU`（有车）/`WU`（无车）；
   - 第 4 行：`Free: 3/3`（空闲车位数）。
2. 串口应打印 `Parking System Ready` 等日志；
3. 此时**卡片数据库是空的**，刷任何卡都会提示 `Unregistered / Access Denied`，需要先注册卡片（见第 5 节）。

---

## 4. 上位机安装与连接

### 4.1 安装

要求 Python 3.10+（Windows 自带 tkinter）：

```powershell
cd 上位机
pip install -r requirements.txt
python parking_client.py
```

首次运行会在同目录创建 `parking.db`（SQLite），卡片、余额、车辆记录都存在这里。

### 4.2 连接设备

1. 用 USB-TTL 连接 STM32 USART1，确认设备管理器里出现 COM 口；
2. 点击左侧 **连接串口**，选择串口、115200，连接；
3. 连接成功后会自动：
   - 同步时间（`SET_TIME`）；
   - 查询车位状态（`GET_STATUS`）；
   - 把本机卡片数据库同步到 STM32（`SYNC_CARD_DB`）。
4. 底部状态栏和右上角指示灯变绿即表示连接正常。

### 4.3 界面结构

| 导航 | 主要功能 |
|---|---|
| 实时监控 | 当前时间（同步/获取时间）、车位状态、系统日志、车辆记录（刷新记录/清空记录） |
| 卡片管理 | 已绑定卡片列表、绑定/更新卡片、删除绑定、黑名单、充值、同步卡片数据库到 STM32 |
| 配置模式 | 进入/退出配置模式、读取/写入卡片、设置车牌/余额/黑名单、收费设置 |

## 5. 注册第一张卡（准备工作）

有两种方式，任选一种。

### 方式 A：上位机卡片管理（推荐，最省事）

1. 把卡片放到 RC522 上，先记录 UID（可以在配置模式读取，或用手机 NFC 工具读取）；
2. 打开 **卡片管理** 页，在“卡片绑定 / 更新”中填写：
   - 卡号 (UID)：8 位十六进制，如 `A1B2C3D4`；
   - 车牌号：如 `京A12345`；
   - 余额：如 `100`；
3. 点击 **绑定/更新**（写入本机数据库）；
4. 点击 **同步卡片数据库到STM32**（把本机所有卡片下发给设备）；
5. 也可以重新连接一次串口，连接时会自动同步。

> 之后这张卡就可以正常刷卡进出场；车牌用于上位机记录显示与出场计费关联。

### 方式 B：配置模式写卡

1. 进入配置模式（见第 7 节）；
2. 把卡放到 RC522 上，OLED 显示 `CARD INFO`；
3. 在上位机配置模式页填写车牌/余额，点击 **写入卡片**；
4. 写入成功后固件会同时把该卡加入内部卡片数据库。

## 6. 车辆进出场操作

### 6.1 刷卡入场

1. 已注册卡片靠近 RC522；
2. OLED 显示 `welcome / CP:车牌 / UID / money:余额`；
3. 入口舵机开闸（约 0.32s 转动 + 2s 保持 + 0.31s 关闸，非阻塞）；
4. 上位机收到入场事件，实时监控的车辆记录新增一条“在场”；
5. 同一张卡连续刷不会重复入场（需要先移开卡片再刷）。

### 6.2 刷卡出场

1. 同一张卡再次刷卡；
2. OLED 显示 `Wait Fee...`，出口舵机开闸；
3. 固件上报出场事件（费用字段为 0），上位机按计费规则算费并回传；
4. 上位机扣减卡余额、更新记录，OLED 显示 `goodbye / CP / UID / fee:xx bal:xx`；
5. 车位释放，红外状态/上位机车位显示同步更新。

> 如果上位机没有连接：道闸仍会打开，但 OLED 会停留在 `Wait Fee...`，费用不会回写；建议进场/出场时保持上位机连接。

### 6.3 MaixCAM 车牌进出场

1. MaixCAM 识别到有效车牌后通过 USART6 发送：
   - `IN:京A12345`（入场）；
   - `OUT:京A12345`（出场）；
2. 固件把中文车牌首字（省份）转成拼音缩写显示在 OLED（OLED 只有 ASCII 字库），
   上报给上位机的仍是原始中文车牌；
3. 车牌入场同样走入口舵机，出场走出口舵机并等待上位机计费；
4. 演示逻辑：同一车牌首次识别判为入场，入场至少 30s 后再次识别才判为出场（`MIN_PARKING_SECONDS`，见第 9 节）。

## 7. 配置模式（读卡/写卡）

### 7.1 进入/退出

- 方式一：按键 **KEY3** 切换（正常模式 ↔ 配置模式）；
- 方式二：上位机 **配置模式** 页 → **进入配置模式 / 退出配置模式**；
- 配置模式下暂停正常的刷卡进出场；
- 60 秒无操作会自动退出（`CONFIG_TIMEOUT_SECONDS`）。

### 7.2 读取卡片

1. 进入配置模式；
2. 把卡片放到 RC522 上，OLED 显示 `CARD INFO` 与卡内信息；
3. 在上位机点击 **读取卡片**，界面显示 UID / 车牌 / 余额 / 黑名单；
4. 如果卡片是 Mifare Classic，使用默认密钥 `FFFFFFFFFFFF` 读 6/7 块；Ultralight 读 0~5 页。

### 7.3 写入/修改卡片

- 修改“车牌号/余额/黑名单”后点击 **写入卡片**：整卡写入；
- 也可以单独点击 **设置车牌 / 设置余额 / 设置黑名单**；
- 写入成功后固件会同步更新内部卡片数据库，上位机数据库也会更新；
- 如果提示失败：检查卡片是否仍在感应区、是否为支持的卡型、默认密钥是否匹配。

### 7.4 收费设置

在配置模式页右侧“收费设置”中：

| 字段 | 含义 |
|---|---|
| 计费方式 | 按小时 / 按分钟（当前算法统一按“分钟周期”计算，保留该选项用于界面展示与后续扩展） |
| 计费时长 | 一个计费周期的分钟数，如 60 = 每小时 |
| 收费金额 | 每个周期的金额（元） |
| 最低收费 | 最低收费（元） |
| 免费时长 | 免费分钟数，不足免费时长不收费 |

改完点击 **应用设置** 下发到 STM32（同时保存到上位机）；点击 **读取设置** 可回读设备当前参数。

计费公式（上位机）：`费用 = max(ceil(max(停车分钟-免费分钟, 1) / 计费时长) × 收费金额, 最低收费)`。

## 8. MaixCAM 车牌识别部署

1. 在 MaixCAM 上安装 MaixPy 运行环境；
2. 把 `LPR/` 目录（`app.yaml`、`main.py`、`pp_ocr.mud` 模型）部署到设备；
3. 确认 OCR 模型路径：`/root/models/pp_ocr.mud`；
4. 串口默认 `/dev/ttyS0`，115200，与 STM32 USART6 **交叉连接**（TX→RX，RX→TX，共地）；
5. 上电运行后，摄像头识别到有效车牌会发送 `IN:车牌` / `OUT:车牌`（UTF-8，换行结尾）；
6. 可在 MaixCAM 屏幕上看到识别结果、UART 状态和最近 5 辆在场车辆。

可调参数（`LPR/main.py` 顶部）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `UART_BAUD` | 115200 | 串口波特率，必须与 STM32 一致 |
| `MIN_PARKING_SECONDS` | 30 | 演示场景：入场后至少 30s 再识别到才判为出场 |
| `DEBOUNCE_TIME` | 2000 | 同一车牌防抖时间（毫秒） |
| `MAX_PLATE_RECORDS` | 128 | 在场记录上限 |

## 10. 数据管理与重新开始

- 车辆记录：实时监控页 **刷新记录 / 清空记录**（清空会下发到 STM32）；
- 卡片列表：卡片管理页 **刷新列表 / 同步卡片数据库到STM32**；
- 删除绑定：卡片管理页选中卡片 → **删除绑定**（只删上位机数据库，设备侧需重新同步；设备重启后卡片数据库为空）；
- 完全重置：关闭上位机，删除 `上位机/parking.db`，重新启动；STM32 重新上电即可；
- 备份：直接复制 `上位机/parking.db`。

## 11. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| 上电 OLED 不亮 | 3.3V/GND、PB10/PB11 接线、OLED 地址 0x78；若刚改过 I2C 时序且花屏，可把 `IIC_delay()` 改回 8~13us |
| 刷卡无反应 | RC522 是否 3.3V、SPI 五根线是否接对、卡是否 Mifare 13.56MHz；看串口是否有 `Card detected` 日志 |
| 提示 `Unregistered` | 卡片未注册，按第 5 节添加卡片并同步数据库 |
| 刷卡后舵机不动 | 舵机独立 5V 电源、PB5/PB6、共地；检查 `Servo_Task()` 是否被主循环调用（本工程已调用） |
| 开闸方向反了 | 调换 `Servo_*_SetSpeed()` 的正负号，或机械上反向安装 |
| 上位机连不上 | 串口号是否正确、驱动（CH340/CP210x）、波特率 115200、串口是否被其他软件占用、是否共地 |
| 上位机收到乱码/断帧 | USART1 同时有 `printf` 调试输出；只能用一个程序占用串口；确认波特率一致 |
| 时间不对 | STM32 无硬件 RTC，默认 2024-04-30，连接上位机后会自动校时；断电后时间复位 |
| 记录/卡片列表显示不全 | 新固件与旧上位机不匹配（多帧列表协议）；请使用仓库内同版本上位机 |
| 车牌不触发 | MaixCAM 与 USART6 是否交叉接线、波特率、模型是否存在、车牌是否符合 `省份+字母+5/6位` |
| 出场没有费用 | 上位机未连接或计费参数未下发；检查 `Wait Fee...` 是否一直停留 |
| Keil 编译失败 | 是否 AC5、是否安装 DFP、C99 是否勾选、宏定义/头文件路径是否正确 |
| 串口日志影响上位机 | 调试时把 `printf` 关掉或改用上位机日志查看；不要同时开串口助手和上位机 |

## 12. 推荐演示流程

1. 上电，OLED 主界面正常，红外状态随遮挡变化；
2. 打开上位机，连接串口，时间同步、状态正常；
3. 卡片管理页添加一张卡并绑定车牌，同步到 STM32；
4. 刷卡 → 入口开闸、OLED 显示 welcome、上位机记录出现“在场”；
5. 再次刷卡 → 出口开闸、上位机计算费用、OLED 显示费用与余额；
6. 进入配置模式，放卡 → 读取/修改车牌或余额 → 写入卡片；
7. MaixCAM 对准车牌 → 识别入场；等待 30s 后再识别 → 出场；
8. 上位机查看车辆记录、卡片列表、收费设置，演示完成。
